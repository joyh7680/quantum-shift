퀀텀시티 STAGE 1 | 블록 수집과 순차 실행

캐릭터의 크기를 바꾸며 거대한 연구실을 탐험한다. 장애물을 넘어 명령 블록을 수집하고, 모은 블록으로 탈출 프로그램을 구성한다. 실행 결과를 관찰하고 순서를 수정해 환풍구로 탈출하는 3D 어드벤처 퍼즐이다.

PART 01

기획 개요

01 기획 기준

이번 안은 사용자가 제안한 블록 아이템 수집 방식을 구체화한 STAGE 1 수정 기획이다. 탐험의 재미와 알고리즘 학습을 하나의 공간에서 연결한다. 아래 획득 도전과 세부 판정은 구현을 위한 제안값이며, 현재 코드에 이미 존재한다는 의미는 아니다.

항목내용
플랫폼과 대상PC 웹 브라우저 · 싱글플레이 · 초등 고학년부터 중학생
화면과 예상 시간실제 3D · 3인칭 시점 · 약 10~15분 목표
학습 방식과 개념블록 코딩 · 알고리즘 · 순차 실행
성공 목표수집한 명령을 올바르게 실행해 정비용 환풍구로 탈출
핵심 흐름탐험 → 도전 성공 → 블록 획득 → 순서 조립 → 실행과 수정 → 탈출

02 플레이어가 하는 일

탐험에서는 키보드로 직접 이동하고 크기를 바꾼다. 코딩에서는 행동 순서를 직접 배치한다. 실행 중에는 프로그램이 캐릭터를 움직이며, 유저는 결과를 관찰한다. 수집 순서는 자유롭고, 실행 순서는 장치 사이의 관계를 보고 판단한다.

03 스테이지 범위

STAGE 1에는 연구실 탐험, 명령 칩 3개 수집, 탈출 프로그램 1개, 클리어 연출을 포함한다. 자연어 요청과 자동 회피 슈트 제작은 STAGE 2에서 사용하도록 분리한다. 기존 레이저 통로와 수호자 전투는 STAGE 1의 필수 진행에서 제외하고 재사용 가능한 상태로 보관한다.

PART 02

탐험 구역과 블록 수집

04 연구실 배치

중앙에 탈출 콘솔과 퍼즐 장치들을 배치하고, 주변 세 갈래 경로에 명령 칩을 둔다. 출발 지점에서 환풍구와 중앙 장치를 볼 수 있게 한다. 책상 위 점프 구간, 전기 바닥 구간, 장비 아래 통로는 원하는 순서로 방문할 수 있다.

수집 구역의 좁은 통로와 최종 탈출 환풍구는 별개다. 세 수집 경로는 탈출 프로그램을 실행하지 않아도 기본 이동·점프·수동 크기 변환만으로 모두 접근할 수 있어야 한다.

수집 블록도전과 획득 조건게임 표현
배터리 연결책과 연필로 만든 발판을 점프해 책상 위 칩에 도달넓은 발판과 안전한 착지점 제공
전원 작동주기적으로 켜지는 전기 바닥을 피해 끝의 칩 획득점등 예고 후 방전 · 안전 구간 표시
환풍구 이동초소형으로 장비 아래 좁은 길을 통과해 칩 획득낮은 입구와 안쪽의 빛으로 위치 안내

05 수집 규칙

칩은 블록 모양의 3D 오브젝트로 표현하고, 가까이 가면 이름을 표시한다. 접촉하면 한 번만 획득하며 보관함으로 날아가는 효과와 짧은 효과음을 제공한다. HUD에는 명령 칩 0/3처럼 수량을 표시한다.

획득한 칩은 명령 사용 권한을 해금한다. 먹는 즉시 배터리를 연결하거나 전원을 켜지는 않는다. 블록은 사용해도 소모되지 않으며, 재시도할 때 다시 수집하지 않는다. 크기 변환 블록 3종은 처음부터 제공한다.

06 조작과 실패 처리

이동 WASD 또는 방향키 / 점프 Space / 카메라 마우스 / 상호작용 E / 크기 변환 1·2·3. 크기 배율은 기존 초소형 0.25배·일반 1배·거대 2.5배를 초기값으로 유지한다.

낙하하거나 전기 바닥에 닿으면 해당 도전 입구로 복귀한다. 획득한 칩은 유지하고 체력·시간 제한은 두지 않는다. 전기 바닥은 주 전원과 별도인 비상 전원으로 작동한다. 최종 환풍구는 정비 전원 공급 시 팬이 정지하도록 설정한다.

PART 03

탈출 프로그램과 실행 규칙

07 문제 제시

처음에는 “연구실의 환풍구를 통해 탈출하세요. 주변을 탐험하며 명령 블록을 찾아보세요.”만 안내한다. 배터리의 무게, 전원 장치의 꺼진 표시등, 회전 중인 환풍구 팬을 관찰 단서로 사용한다. 완성된 코드나 정답 순서는 기본 화면에 노출하지 않는다.

08 사용 가능한 명령

블록동작과 실행 조건
초소형으로 변환주변 공간을 확인하고 크기 변경
일반 크기로 변환확대 공간이 있으면 일반 크기로 변경
거대화충분한 공간이 있는 퍼즐 구역에서 거대 크기로 변경
배터리 연결배터리까지 이동해 소켓에 배치 · 거대 크기 필요
전원 작동조작대까지 이동해 정비 전원 켜기 · 배터리 연결과 일반 크기 필요
환풍구 이동입구까지 이동해 내부 통과 · 팬 정지와 초소형 크기 필요

일반 크기 조건은 작은 정밀 조작대를 조작하는 동작으로 표현한다. 거대 상태에서는 손이 커서 조작할 수 없고, 초소형 상태에서는 손이 닿지 않는 모습을 보여준다. 정비 전원이 켜지면 팬이 감속한 뒤 완전히 멈춘다.

09 개발용 성공 예시

거대화 → 배터리 연결 → 일반 크기로 변환 → 전원 작동 → 초소형으로 변환 → 환풍구 이동

위 순서는 기획과 검증을 위한 예시이며 학생 화면에는 정답으로 표시하지 않는다. 실행은 배열 일치 비교가 아니라 현재 크기·배터리 연결·정비 전원·팬 상태에 따라 각 행동을 처리한다. 불필요한 변환이 있어도 모든 조건을 충족하고 출구에 도달하면 성공한다.

10 실제 3D 실행

실행을 시작하면 캐릭터는 콘솔 옆의 넓은 출발 지점에서 일반 크기로 시작한다. 장치 이동은 미리 지정한 안전 경로를 사용하고, 배터리 운반·스위치 조작·환풍구 통과를 실제 장면에서 보여준다. 거대 상태에서도 배터리까지 이동 가능한 경로와 천장 높이를 확보한다.

최종 퍼즐 장치는 프로그램으로 작동시키는 설비로 구분한다. 탐험 중 E는 장치 관찰과 콘솔 열기에 사용하고, 직접 장치를 완료하거나 출구를 우회할 수 없게 한다. 실행 중 수동 이동·크기 변경·코드 편집은 잠근다.

PART 04

화면 구성과 학습 피드백

11 탐험 화면

왼쪽 상단에는 탈출 목표와 명령 칩 수집 수량, 하단에는 현재 크기와 조작 안내를 표시한다. 수집한 칩은 작은 아이콘으로 보관함에 추가한다. 획득 순서가 실행 순서라고 오해하지 않도록 보관함에 순서 번호를 붙이지 않는다.

12 코딩 화면

탈출 콘솔에서 E를 누르면 카메라가 중앙 퍼즐 구역을 내려다보는 시점으로 전환된다. 왼쪽 약 60%에는 실제 캐릭터와 장치가 보이는 3D 장면, 오른쪽 약 40%에는 블록 보관함과 내 코드를 배치한다. 모달 뒤에 게임이 가려지는 방식 대신 장면과 편집기를 함께 보여준다.

내 코드는 빈 상태로 시작한다. 클릭 또는 드래그로 추가하고, 순서 변경·삭제·전체 초기화를 지원한다. 보관함의 명령은 반복 사용 가능하다. 칩을 다 모으기 전에도 콘솔에서 확인과 편집은 가능하지만 실행은 잠그고 부족한 칩 수만 안내한다.

주요 버튼은 실행·실행 중단·초기화·탐험으로 돌아가기다. 빈 코드에서는 실행을 비활성화한다. 실행 중에는 현재 블록을 강조하고, 카메라는 행동을 따라가되 장치가 보이는 구도를 유지한다.

13 실패와 재실행

상황피드백
배터리 없이 전원 작동배터리가 연결되지 않았어요.
일반 크기로 배터리 연결배터리가 너무 무거워요.
팬이 회전 중인데 환풍구 이동팬이 돌아가고 있어 통과할 수 없어요.
큰 상태로 환풍구 이동입구가 좁아 현재 크기로는 들어갈 수 없어요.
프로그램 종료 후 미탈출명령이 끝났지만 출구에 도착하지 못했어요.

실패한 블록에서 실행을 멈추고 원인만 표시한다. 다음 정답 블록을 자동으로 넣지 않는다. 재실행·중단·탐험 복귀 시 퍼즐의 캐릭터 위치·크기·배터리·전원·팬을 시작 상태로 복원한다. 수집 칩과 작성한 코드는 유지하고, 전체 초기화는 작성 코드만 비운다.

14 도움과 난이도

기본 난이도는 칩 3개와 블록 종류 6개다. 시간 제한과 미끼 블록은 넣지 않는다. 도움말은 선택 시에만 관찰 질문을 제공한다. 예를 들어 “팬을 멈추려면 어떤 장치가 필요할까요?”처럼 안내하며 완성된 순서는 보여주지 않는다.

17 구현 순서와 완료 기준

현재 버전을 보존한 뒤 ① 기존 스테이지 의존성 분리 ② 수집 도전과 인벤토리 ③ 행동 명령 실행 ④ 코딩 화면과 피드백 ⑤ 탈출·재시작·안내 문구 순으로 작업한다.

완료 확인: 세 경로를 어느 순서로 방문해도 칩을 모을 수 있다. 획득 시 장치가 자동 완료되지 않는다. 잘못된 순서는 해당 행동에서 멈춘다. 성공 프로그램은 실제 장면에서 탈출까지 수행된다. 재시도 시 장치는 복원되고 칩과 코드는 유지된다. 탐험으로 나갔다 돌아와도 편집 내용을 유지한다. STAGE 1에서 바이브 코딩이나 자동 축소를 요구하지 않는다.

플레이 검증에서는 학생이 다음 순서를 고른 이유를 설명할 수 있는지 확인한다. 막히는 원인이 조작 난이도인지, 장치 단서 부족인지, 실행 순서 오해인지 구분해 조정한다. 안내와 테스트를 포함해 약 10~15분에 완주하는 것을 목표로 한다.
