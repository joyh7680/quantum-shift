# QUANTUM CITY — 퀀텀시티

React + TypeScript + Vite / Three.js + React Three Fiber / Rapier로 구현한 실제 3D 웹 게임입니다. 코드모스 GLB는 플레이어에만 사용하며 연구실, 가구, 장치, 레이저, 로봇은 코드로 제작했습니다.

## 실행

Node.js 22 이상 권장. 프로젝트 폴더에서 실행합니다.

```powershell
npm install
npm run dev
```

터미널에 출력되는 로컬 주소를 Chrome 또는 Edge에서 엽니다. 기본 주소는 http://localhost:5173 입니다. `file://`로 열면 모델을 로드할 수 없습니다. 실행에 API 키나 외부 모델 다운로드가 필요하지 않습니다.

```powershell
npm test          # 명령 순서, 요청 거절, 축소/복귀, 스테이지 분리·전환·전투
npm run build    # TypeScript 검사 + dist 프로덕션 빌드
npm run preview  # 빌드 결과 실행
npm run audit:assets
```

## 메인 메뉴

첫 접속과 새로고침 시에는 QUANTUM CITY 타이틀 화면이 표시됩니다. 선택한 코드모스 캐릭터, 절차적으로 제작한 미래 도시·연구 시설, 에너지 링·입자, 느린 카메라 이동을 보여줍니다. 모션 감소 설정에서는 카메라와 링의 이동을 멈춥니다.

- 게임 시작: 선택한 캐릭터로 STAGE 1 거인의 연구실에 진입합니다.
- 캐릭터 선택: 기존 47종을 선택하며 메인 화면과 플레이어에 동일하게 적용합니다.
- 캐릭터 옵션은 원본 GLB를 정면 렌더링한 얼굴 썸네일·이름·선택 체크를 표시합니다. 선택창을 닫아도 선택 버튼에 현재 캐릭터의 썸네일과 이름이 유지됩니다.
- 스테이지 안내: 5개 스테이지의 경로와 학습 목표·주요 플레이를 확인합니다. STAGE 1 클리어 후 STAGE 2가 해금되며, 클리어 화면이나 스테이지 안내에서 진입할 수 있습니다. STAGE 3~5는 준비 중으로 진입이 잠겨 있습니다.
- 모달은 닫기 버튼, 배경 클릭, ESC로 닫히며 키보드 포커스가 열었던 버튼으로 복귀합니다.
- 메인 메뉴에서는 게임 플레이어·물리·이동 입력·포인터 잠금이 연결되지 않습니다. 게임의 일시정지 화면과 클리어 화면에서 메인 메뉴로 돌아갈 수 있습니다. 복귀 시 선택한 캐릭터와 두 스테이지의 진행·클리어 기록을 세션 내에서 유지합니다. 스테이지 시작 버튼은 해당 스테이지만 처음부터 시작합니다.

## 조작

| 입력 | 동작 |
|---|---|
| WASD 또는 방향키 | 카메라 방향 기준 이동 |
| Space | 점프 |
| 게임 화면 클릭 + 마우스 | 포인터 잠금 / 3인칭 카메라 회전 |
| 1 / 2 / 3 | 초소형 0.25× / 일반 1× / 거대 2.5× |
| E | STAGE 1 콘솔 열기·장치 관찰 / STAGE 2 장치 조작·약점 공격 |
| Q | STAGE 2 자동 축소 능력 ON/OFF |
| Esc 또는 우측 상단 Ⅱ | 일시정지 / 마우스 잠금 해제 |

패널을 닫고 화면을 다시 클릭하면 마우스 카메라가 재개됩니다. STAGE 1 코딩 패널에서는 실제 연구실에서 프로그램이 실행됩니다. STAGE 2 슈트 패널에서는 본 게임을 일시정지하고 별도 3D 테스트 화면을 실행합니다.

## 진행

### STAGE 1 — 거인의 연구실

코딩 방식: **블록 코딩** / 학습 목표: **알고리즘 · 순차 실행**

- 자유 탐험: 책·연필 발판 점프, 비상 전기 바닥의 안전 주기, 분석 장비 아래 초소형 통로에서 명령 칩 3개를 원하는 순서로 수집합니다. 칩은 행동 사용 권한만 해금하며 장치를 작동시키지 않습니다. 낙하·감전 시 해당 도전 입구로 복귀하며 칩은 유지됩니다.
- 중앙 탈출 콘솔에서 E: 왼쪽 60%에 실제 3D 연구실, 오른쪽 40%에 보관함과 빈 내 코드를 표시합니다. 클릭·드래그 추가, 순서 이동, 삭제, 초기화를 지원하고 같은 블록을 여러 번 쓸 수 있습니다. 크기 변환 3종은 기본 제공됩니다.
- 실행: 캐릭터가 안전 경로를 따라 배터리를 운반하고 정밀 조작대를 누르면 정비 팬이 감속 후 정지합니다. 각 명령은 현재 크기·배터리·전원·팬 조건을 검사하며 정답 배열을 비교하지 않습니다. 프로그램으로 실제 환풍구를 통과해야 클리어됩니다.
- 실행 중 수동 조작·코드 편집은 잠기고 현재 블록이 강조됩니다. 실패 원인만 표시하며 재실행·중단·탐험 복귀는 위치·크기·장치 상태를 복원합니다. 수집 칩과 작성 코드는 유지됩니다. 초기화는 코드만 비웁니다.
- 탐험에서 장치는 관찰만 가능하며 출구는 잠겨 있어 코딩을 건너뛸 수 없습니다. 슈트·레이저·수호자는 STAGE 2에 유지됩니다.

기획서: `docs/Quantum_City_Stage1_Plan.html`. 기존 수정본 백업: `artifacts/pre-stage1-blocks/`.

### STAGE 2 — 마이크로 회로

학습 목표: **바이브 코딩 · 조건문**

1. 기존 보라색 슈트 콘솔 앞 구역에서 시작합니다. 일반 크기로 콘솔을 조작하고 자연어 입력 → 능력 생성 → 테스트 → 장착을 진행합니다. 레이저 감지, 자동 축소, 이전 크기 기억, 공간 확인 후 복귀 기능을 재사용합니다.
2. 자동 축소를 켜고 기존 레이저 통로를 통과합니다. 끝의 낮은 구조물 아래에서는 복귀할 공간이 생길 때까지 초소형을 유지합니다.
3. 수호자의 충전 → 발사에 맞춰 자동 축소로 회피하면 약점이 노출됩니다. 거대화 후 가까이에서 E로 약점을 3회 공격하고, 열린 민트색 탈출문으로 나가면 STAGE 2가 클리어됩니다.

컴퓨터 내부 탐험 및 회로 복구는 향후 확장 범위이며 이번 작업에는 추가하지 않았습니다. 기존 공간과 장치를 스테이지 경계에 맞게 분리해 재사용합니다.

레이저 피격 또는 낙하 시 **현재 스테이지**의 체크포인트에서 재시작합니다. 배터리·전력은 STAGE 1, 슈트 개발·장착·수호자 코어는 STAGE 2가 각각 소유합니다. 미션, 체크포인트, 시간, 재시작 횟수, 클리어 상태도 독립적입니다. STAGE 2를 진행하거나 재시작해도 STAGE 1의 완료 기록과 통계는 바뀌지 않습니다. 진행은 현재 플레이 세션 내에서 유지되며 새로고침 시 초기화됩니다.

## 에셋

- GLB 148개의 헤더·JSON 청크·SHA-256·메시·노드·재질·텍스처·애니메이션을 검사했습니다. 캐릭터는 중복 없이 47종입니다.
- 우주 탐사와 어울리는 노바, 제트, 보라, 포비, 레미, 테오, M254, 암스트롱을 먼저 표시하며 전체 47종도 선택할 수 있습니다.
- 우주여행 폴더에는 우주선만 있습니다. 캐릭터는 `models/dosan-park/characters`에 있으며 회사 소품과 우주선은 게임에 로드하지 않습니다.
- 캐릭터에 원본 애니메이션 클립이 없어 팔·다리 부위에 회전축을 추가했습니다. 실제 충돌 처리 후 이동 속도와 크기에 맞춰 팔다리를 번갈아 움직이며, 발바닥 접지·점프 자세·정지 전환·일시정지를 지원합니다. 원본 메시와 재질은 유지합니다.
- 실제 바운딩 박스로 중심·바닥·높이·폭을 정규화하고 모든 캐릭터에 같은 Rapier 캡슐과 조작 규칙을 적용합니다.
- 브라우저는 `/codmos-glb-assets-2026-10-15/models/...glb` URL을 사용합니다. 로드 오류는 화면에 표시하며 임의 캐릭터로 대체하지 않습니다.
- 검사 결과: [artifacts/asset-audit.json](artifacts/asset-audit.json)
- 프로덕션 빌드에는 플레이어 캐릭터 47종만 포함하며 사용하지 않는 회사 소품과 우주선은 제외합니다. 제공된 원본 폴더는 그대로 보존합니다.
- `public/character-thumbnails/`의 47종 PNG는 같은 ID의 GLB에서 생성했습니다. `manifest.json`에 원본 URL과 SHA-256을 기록합니다. 개발 서버 실행 후 `node scripts/render-character-thumbnails.mjs`로 다시 생성할 수 있으며, `QC_QA_URL`로 서버 주소를 지정합니다. 썸네일은 프로덕션 빌드에도 포함됩니다.

## 브라우저 검증

개발 서버 실행 상태에서:

```powershell
node scripts/menu-smoke.mjs       # 기본 5173, QC_QA_URL로 실제 개발 서버 지정
node scripts/character-ui-qa.mjs  # 47종 썸네일 매칭, 선택 동기화, 데스크톱·모바일 배치
node scripts/character-walk-qa.mjs # 실제 이동·정지·벽 충돌·점프·크기별 보행·자동 이동
node scripts/lab-smoke.mjs        # STAGE 1 수집·충돌·실패·중단·수정·실제 탈출
node scripts/playthrough.mjs      # STAGE 1 → STAGE 2 전체 진행, QC_QA_URL 지정 가능
node scripts/asset-browser-qa.mjs
node scripts/stage2-smoke.mjs     # STAGE 2 단독 회귀 검증
```

슈트 제작 화면만 검증하려면 `$env:QC_QA_SUIT_ONLY = '1'`을 설정한 뒤 `node scripts/playthrough.mjs`를 실행하세요. 빈 입력·공백 입력 잠금, 도움말, 코드 생성, 테스트, 수정 후 재생성·재테스트, 패널 재진입, 장착을 확인합니다.

스크립트는 Windows에 설치된 Chrome을 사용합니다. 다른 환경은 executablePath를 변경하거나 Playwright 브라우저를 설치하세요. STAGE 1 검증은 칩이나 캐릭터 위치를 주입하지 않고 실제 키보드로 통로·발판·전기 바닥을 진행합니다. 잘못된 명령 실패, 운반 중 중단과 복원, 코드 유지·순서 변경·드래그, 편집 잠금, 팬 감속, 실제 환풍구 도달을 확인합니다. 결과와 화면은 artifacts/lab-result.json 및 artifacts/lab-*.png에 저장됩니다. STAGE 2 회귀 검증은 scripts/stage2-smoke.mjs로 별도 실행할 수도 있습니다.
STAGE 1은 로컬 HTML 기획서 전체와 추가 요구사항을 기준으로 구현했습니다.

STAGE 1 → STAGE 2 연결을 집중 검증하려면 `QC_QA_STAGE1_TRANSITION=1`을 설정하고 `scripts/stage2-smoke.mjs`를 실행하세요. 이 모드는 칩과 코드를 개발용 준비 상태로 설정한 뒤 실제 3D 프로그램 실행·탈출·클리어 버튼을 거쳐 STAGE 2의 세 미션을 키보드와 UI로 검증합니다. 칩 수집을 포함한 전체 경로는 `scripts/lab-smoke.mjs` 또는 `scripts/playthrough.mjs`로 검증합니다.

STAGE 1 최종 검증 요약: [artifacts/stage1-verification.json](artifacts/stage1-verification.json). 수집 포함 전체 검증과 장치 실행 집중 검증을 분리해 기록하며, 집중 검증의 개발용 fixture 사용 범위도 결과에 표시합니다.
