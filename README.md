# QUANTUM CITY — 퀀텀시티

React + TypeScript + Vite / Three.js + React Three Fiber / Rapier로 구현한 실제 3D 웹 게임입니다. 코드모스 GLB는 플레이어에만 사용하며 연구실, 가구, 장치, 레이저, 로봇은 코드로 제작했습니다.

## 실행

Node.js 22 이상 권장. 프로젝트 폴더에서 실행합니다.

```powershell
npm install
npm run dev
```

터미널에 출력되는 로컬 주소를 Chrome 또는 Edge에서 엽니다. 기본 주소는 http://localhost:5173 입니다. `file://`로 열면 모델을 로드할 수 없습니다. 실행에 API 키나 외부 모델 다운로드가 필요하지 않습니다.

```powershell
npm test          # 명령 순서, 요청 거절, 축소/복귀 규칙
npm run build    # TypeScript 검사 + dist 프로덕션 빌드
npm run preview  # 빌드 결과 실행
npm run audit:assets
```

## 메인 메뉴

첫 접속과 새로고침 시에는 QUANTUM CITY 타이틀 화면이 표시됩니다. 선택한 코드모스 캐릭터, 절차적으로 제작한 미래 도시·연구 시설, 에너지 링·입자, 느린 카메라 이동을 보여줍니다. 모션 감소 설정에서는 카메라와 링의 이동을 멈춥니다.

- 게임 시작: 선택한 캐릭터로 STAGE 1 거인의 연구실에 진입합니다.
- 캐릭터 선택: 기존 47종을 선택하며 메인 화면과 플레이어에 동일하게 적용합니다.
- 캐릭터 옵션은 원본 GLB를 정면 렌더링한 얼굴 썸네일·이름·선택 체크를 표시합니다. 선택창을 닫아도 선택 버튼에 현재 캐릭터의 썸네일과 이름이 유지됩니다.
- 스테이지 안내: 5개 스테이지의 경로와 목표·주요 플레이를 확인합니다. STAGE 1만 플레이 가능하며, STAGE 2~4는 확인된 기획 데이터가 없어 미공개 구역으로, STAGE 5는 거대 로봇 보스로 표시합니다. 미구현 구역의 진입은 잠겨 있습니다.
- 모달은 닫기 버튼, 배경 클릭, ESC로 닫히며 키보드 포커스가 열었던 버튼으로 복귀합니다.
- 메인 메뉴에서는 게임 플레이어·물리·이동 입력·포인터 잠금이 연결되지 않습니다. 게임의 일시정지 화면과 클리어 화면에서 메인 메뉴로 돌아갈 수 있습니다. 복귀 시 선택한 캐릭터는 유지되며 진행은 초기화됩니다.

## 조작

| 입력 | 동작 |
|---|---|
| WASD | 카메라 방향 기준 이동 |
| Space | 점프 |
| 게임 화면 클릭 + 마우스 | 포인터 잠금 / 3인칭 카메라 회전 |
| 1 / 2 / 3 | 초소형 0.25× / 일반 1× / 거대 2.5× |
| E | 장치 조작, 배터리 운반·연결, 약점 공격 |
| Q | 자동 축소 능력 ON/OFF |
| Esc 또는 우측 상단 Ⅱ | 일시정지 / 마우스 잠금 해제 |

패널을 닫고 화면을 다시 클릭하면 마우스 카메라가 재개됩니다. 코딩 패널에서는 본 게임과 물리를 일시정지하며 별도의 3D 테스트 화면만 실행합니다.

## 진행

1. 거대한 책상 사이에서 이동, 점프, 크기 변환을 익힙니다.
2. 초소형으로 정면 환풍구를 통과합니다. 내부에서는 확대할 수 없습니다.
3. 거대화하여 주황색 배터리를 E로 들고 발전기 링에서 E로 연결합니다. 일반 크기로 전원 콘솔을 열고 `메인 전원 → A → B → C`를 클릭하거나 원하는 빈 슬롯으로 드래그하여 배치합니다.
4. 다음 방의 보라색 슈트 콘솔을 일반 크기로 조작합니다. 레이저 접근 시 축소하고 통과 후 이전 크기로 복귀하는 요청을 입력합니다. 생성 → 테스트 → 장착이 완료되어야 통로가 열립니다.
5. 자동 축소를 켜고 레이저 구역을 통과합니다. 끝의 낮은 구조물 아래에서는 복귀할 공간이 생길 때까지 초소형을 유지합니다.
6. 경비 로봇은 충전 → 발사 → 자동 축소 회피 성공 시 약점 노출 순서로 행동합니다. 가까이에서 거대화 후 E로 약점을 3회 공격하세요.
7. 로봇 옆으로 돌아 민트색 출구로 나가면 클리어 화면과 다시 시작이 표시됩니다.

레이저 피격 또는 낙하 시 구역 체크포인트에서 재시작합니다. 복구한 전력, 장착한 능력, 파괴한 보스 코어는 유지됩니다. 진행은 현재 플레이 세션 내에서 유지되며 새로고침 시 초기화됩니다.

## 에셋

- GLB 148개의 헤더·JSON 청크·SHA-256·메시·노드·재질·텍스처·애니메이션을 검사했습니다. 캐릭터는 중복 없이 47종입니다.
- 우주 탐사와 어울리는 노바, 제트, 보라, 포비, 레미, 테오, M254, 암스트롱을 먼저 표시하며 전체 47종도 선택할 수 있습니다.
- 우주여행 폴더에는 우주선만 있습니다. 캐릭터는 `models/dosan-park/characters`에 있으며 회사 소품과 우주선은 게임에 로드하지 않습니다.
- 캐릭터에 리깅과 애니메이션 클립이 없어 원본 재질을 유지한 채 몸체 바운스·기울기·점프 자세를 절차적으로 보완합니다.
- 실제 바운딩 박스로 중심·바닥·높이·폭을 정규화하고 모든 캐릭터에 같은 Rapier 캡슐과 조작 규칙을 적용합니다.
- 브라우저는 `/codmos-glb-assets-2026-10-15/models/...glb` URL을 사용합니다. 로드 오류는 화면에 표시하며 임의 캐릭터로 대체하지 않습니다.
- 검사 결과: [artifacts/asset-audit.json](artifacts/asset-audit.json)
- 프로덕션 빌드에는 플레이어 캐릭터 47종만 포함하며 사용하지 않는 회사 소품과 우주선은 제외합니다. 제공된 원본 폴더는 그대로 보존합니다.
- `public/character-thumbnails/`의 47종 PNG는 같은 ID의 GLB에서 생성했습니다. `manifest.json`에 원본 URL과 SHA-256을 기록합니다. 개발 서버 실행 후 `node scripts/render-character-thumbnails.mjs`로 다시 생성할 수 있으며, `QC_QA_URL`로 서버 주소를 지정합니다. 썸네일은 프로덕션 빌드에도 포함됩니다.

## 코드 구조

| 파일 | 책임 |
|---|---|
| `src/Player.tsx` | Rapier 이동·점프·크기별 충돌, 공간 검사, 레이저/보스, 카메라 Raycast |
| `src/World.tsx` | 직접 제작한 연구실 메시, 배터리, 문, 레이저, 로봇 |
| `src/Character.tsx` | GLB 로드·정규화·동작 보완 |
| `src/rules.ts` | 지원 요청 판별, 허용 슈트 명령, 전원 알고리즘 |
| `src/Panels.tsx` | 전원 퍼즐, 능력 생성·수정·테스트·장착 |
| `src/store.ts` | 미션, 체크포인트, 전력, 능력, 보스 상태 |
| `src/App.tsx` | 메인/게임 화면 전환, HUD, 클리어, 오류 처리 |
| `src/MainMenu.tsx` | 타이틀 메뉴, 캐릭터 선택, 스테이지 모달 |
| `src/TitleScene.tsx` | 절차적 도시·연구 시설, 에너지 링·입자, 타이틀 카메라 |
| `src/stages.ts` | 도시의 5개 스테이지 정보·플레이 가능 상태 |

슈트 개발은 **AI 시뮬레이션**입니다. 지원 조건과 명령만 구조화된 프로그램으로 변환합니다. 생성 코드 문자열을 실행하거나 `eval`하지 않습니다. 실제 LLM 연동과 임의의 능력 생성은 포함하지 않습니다.

## 브라우저 검증

개발 서버 실행 상태에서:

```powershell
node scripts/menu-smoke.mjs       # 기본 5173, QC_QA_URL로 실제 개발 서버 지정
node scripts/character-ui-qa.mjs  # 47종 썸네일 매칭, 선택 동기화, 데스크톱·모바일 배치
node scripts/playthrough.mjs      # QC_QA_URL로 실제 개발 서버 지정
node scripts/asset-browser-qa.mjs
```

슈트 제작 화면만 검증하려면 `$env:QC_QA_SUIT_ONLY = '1'`을 설정한 뒤 `node scripts/playthrough.mjs`를 실행하세요. 빈 입력·공백 입력 잠금, 도움말, 코드 생성, 테스트, 수정 후 재생성·재테스트, 패널 재진입, 장착을 확인합니다.

스크립트는 Windows에 설치된 Chrome을 사용합니다. 다른 환경은 `executablePath`를 변경하거나 Playwright 브라우저를 설치하세요. 플레이 검증은 진행을 건너뛰지 않고 키보드와 UI로 환풍구, 배터리, 잘못된/올바른 순서, 요청 거절, 패널 일시정지, 테스트 전 장착 잠금, 피격 재시작, 자동 축소/복귀 보류, 보스 3회 공격, 탈출, 다시 시작을 확인합니다. 결과와 화면은 `artifacts/`에 저장됩니다.

기획서 공유 링크는 개발 환경에서 본문을 가져오지 못해 요청 메시지의 상세 요구사항을 기준으로 구현했습니다.
